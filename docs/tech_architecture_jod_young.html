📌 1. บทสรุปสถาปัตยกรรมระดับผู้บริหาร (Executive Blueprint)

"จดยัง" ถูกออกแบบมาเพื่อตอบโจทย์ผู้ใช้งานที่ต้องการบันทึกรายรับ-รายจ่ายที่ "เร็วที่สุด ลดแรงต้านการจด (Frictionless Entry)" พร้อมระบบควบคุมสุขภาพการเงินรอบด้าน (Daily Budget Pacing, Credit Card Cut/Due Tracker, Financial Goal Plans) โดยมีหลักการออกแบบเชิงสถาปัตยกรรม 4 เสาหลัก:

⚡ 1. High Velocity & Low Latency Vercel Edge

สถาปัตยกรรม Jamstack ส่งมอบ Asset ผ่าน Global Edge CDN ร่วมกับ Go Serverless Backend Binary ขนาดเล็ก Cold-start ต่ำกว่า 120ms และรัน API Sub-millisecond (< 2ms)

🧱 2. Hexagonal Clean Architecture Ports & Adapters

แยก Business Logic (Domain & Core Services) ออกจาก Infrastructure สลับระหว่าง TiDB Cloud (MySQL Engine) และ Local JSON Store โดยไม่ต้องแก้โค้ดทางธุรกิจแม้แต่บรรทัดเดียว

🧠 3. Thai NLP Parser Tokenizer In-Memory Engine

อัลกอริทึม Tokenization ภาษาไทยแบบ Pure Go ทำงานร่วมกับ Regular Expression สกัดหา "จำนวนเงิน", "ชื่อรายการ", "หมวดหมู่อัตโนมัติ" และ "บัญชีตัดยอด" ได้ในเวลาไม่ถึง 0.05ms

☁️ 4. Distributed Resilience Database TiDB Serverless

ฐานข้อมูล NewSQL แยก Compute (TiDB Server) ออกจาก Storage (TiKV Engine) ปลอดภัยด้วย TLS Enforce ในภูมิภาคสิงคโปร์ (AWS ap-southeast-1) ข้อมูลการเงินถูกต้อง 100% ตามมาตรฐาน ACID

🏛️ 3. สถาปัตยกรรม Hexagonal (Ports & Adapters Architecture)

ระบบฝั่ง Backend ถูกวางโครงสร้างตามหลักการ Hexagonal Architecture (Clean Architecture) เพื่อให้ Business Rules เป็นอิสระจาก Framework, Database หรือช่องทางการรับคำขอใด ๆ:

1. Driving Adapters (Inbound / จุดรับคำขอภายนอก)
Fiber HTTP Router (`pkg/adapters/handlers/fiber`)
RESTful Endpoints: `/api/summary`, `/api/transactions`, `/api/parse`
Vercel Serverless Entrypoint (`api/index.go`)
Vercel HTTP Handler Wrapper ผ่าน Fiber Adaptor
2. Inbound & Outbound Ports (อินเตอร์เฟสสัญญาการทำงาน)
AppServicePort
`GetSummary()`, `AddTransaction()`
ParserServicePort
`ParseExpense(rawText string)`
RepositoryPort
`GetStore()`, `SaveTransaction()`
3. Core Services & Domain Models (หัวใจทางธุรกิจ)
Domain Entities (`pkg/core/domain`)
`Transaction`, `Account`, `Card`, `FixedExpense`, `Plan`, `Debt`
Core Logic (`pkg/core/services`)
Balance Reconciler, Daily Pacing Calculator, Thai Tokenizer
4. Driven Adapters (Outbound / ที่เก็บข้อมูลภายนอก)
TiDB Cloud Storage Adapter (`pkg/adapters/storage`)
SQL Queries, Connection Pooling, Auto Migration, TLS Config
Local JSON Fallback Storage
File System Persistence เมื่อทดสอบใน Local หรือรัน Unit Tests

โครงสร้างสารบัญไฟล์ในโปรเจกต์ (Clean Directory Layout)

├── api/index.go                     # Vercel Serverless Function Entrypoint
├── main.go                          # Standalone Local Fiber HTTP Server
├── pkg/
│   ├── core/
│   │   ├── domain/models.go         # Domain Entities, DTOs & Request/Response Structs
│   │   ├── ports/ports.go           # Primary & Secondary Ports (Interfaces)
│   │   └── services/
│   │       ├── app_service.go       # Financial Business Logic & Balance Reconciler
│   │       └── parser_service.go    # Thai NLP Regular Expression Tokenizer
│   └── adapters/
│       ├── handlers/fiber/router.go # Fiber HTTP Handlers & Middlewares
│       └── storage/storage.go       # TiDB Cloud MySQL Implementation & Schema Migration
└── frontend/
    ├── src/
    │   ├── components/              # HomeTab, AddTab, BankTab, PlanTab, Modals, AppLoadingScreen
    │   └── services/api.js          # REST Client (Fetch API with graceful Fallback)

🗄️ 4. สกีมาฐานข้อมูล & ผังการทำงาน (Schema & Workflows)

โครงสร้างตารางในฐานข้อมูล TiDB Cloud (Data Schema Specification)

ชื่อตาราง คอลัมน์สำคัญ (Key Fields) วัตถุประสงค์และการรักษาความถูกต้อง (Integrity)
accounts `id` (PK), `name`, `role`, `amount`, `tint`, `updated_at` เก็บบัญชีเงินสด/เงินฝาก เช่น "บัญชีใช้จ่าย", "เติมน้ำมัน", "Saving" มีการปรับยอด Real-time
cards `id` (PK), `name`, `cut_day`, `due_date`, `limit_amount`, `amount`, `tint` เก็บบัตรเครดิตพร้อมรอบบิล (วันตัดรอบ / วันครบกำหนดชำระ) คำนวณวงเงินคงเหลือและ % หนี้บัตร
transactions `id` (PK), `title`, `amount`, `category`, `account`, `is_income`, `date`, `when_text` สมุดบัญชีรายรับ-รายจ่าย (Immutable Audit Trail) บันทึกทุกธุรกรรมพร้อม Timestamp ภาษาไทย
fixed_expenses `id` (PK), `name`, `amount`, `day`, `done`, `category` รายการค่าใช้จ่ายคงที่รายเดือน (ค่าน้ำ, ค่าไฟ, ค่าหอ) มีระบบแจ้งเตือนเมื่อใกล้ครบกำหนด 7 วัน
plans `id` (PK), `title`, `total_amount`, `paid_amount`, `monthly_amount`, `due_day` แผนการออมเงิน หรือรายการผ่อนชำระสินค้า คำนวณความคืบหน้ารายเดือนและจำนวนงวดที่เหลือ

ผังกระบวนการบันทึกรายการด่วน (Quick Recording Flow)

1
Input Phase: ผู้ใช้ป้อนข้อความหรือสั่งงานด้วยเสียง
เช่น พิมพ์ว่า "ข้าวกะเพราหมูกรอบ 65 บัญชีใช้จ่าย" หรือใช้ Web Speech API บันทึกเสียงพูดภาษาไทย
2
NLP Engine Phase: ถอดรหัสข้อความด้วย Parser Service
Go Parser Service สกัดตัวเลข 65 ➔ ตรวจจับคำว่า "กะเพรา" แมปหมวดหมู่ "อาหาร" ➔ แมปเข้า "บัญชีใช้จ่าย"
3
Atomic Execution Phase: ประมวลผลและปรับยอดบัญชีพร้อมกัน
AppService บันทึกลงตาราง transactions พร้อมสั่งปรับยอดเงินในตาราง accounts (หักออก 65 บ.) หรือปรับยอดหนี้ใน cards Real-time
4
Pacing Re-calculation Phase: คำนวณงบประมาณคงเหลือรายวันใหม่
ระบบคำนวณงบรายจ่ายคงเหลือของวันนั้นใหม่ทันที (Left to Spend / Remaining Days in Month) ส่งกลับไปแสดงผลที่หน้าจอ

ผังการแก้ไขธุรกรรม (Transaction Edit & Balance Reversal Engine)

กลไก Balance Reversal & Apply: เมื่อมีการแก้ไขตัวเลขหรือสลับบัญชี ระบบจะทำการ Revert (คืนยอดเดิม) ให้กับบัญชีเก่าก่อนเสมอ แล้วจึงนำยอดใหม่ไป Apply (หัก/เพิ่ม) ให้กับบัญชีใหม่ เพื่อป้องกันปัญหายอดเงินคงเหลือผิดเพี้ยนเด็ดขาด

🔒 มาตรการความปลอดภัย (Security) Enforced
  • Data in Transit: บังคับเชื่อมต่อผ่าน HTTPS (TLS 1.3) ตลอดเส้นทาง Client-to-Vercel และ Vercel-to-TiDB Cloud
  • No Secrets in Source: `.env` และข้อมูล Database Credentials ถูกกีดกันด้วย `.gitignore` อย่างเคร่งครัด
  • App Lock: รองรับการตั้งรหัสผ่าน 4 หลัก (PIN Lock) ป้องกันการเปิดดูจากบุคคลรอบตัว
  • SQL Shield: คำสั่ง SQL ใช้ Prepared Statements ผ่าน `database/sql` 100%
🛡️ ความต่อเนื่องในการทำงาน (Resilience) Resilient
  • Dual-Layer Fallback: หากการเชื่อมต่อคลาวด์ขัดข้อง สลับไปอ่าน Local Storage ทันที
  • Optimistic UI Updates: แสดงผลรายการทันทีขณะรอ Network ช่วยให้แอปตอบสนองไว
  • Connection Pool Tuning: ตั้ง `SetMaxOpenConns(5)` และ `SetMaxIdleConns(3)` ป้องกัน Connection รั่วไหล
